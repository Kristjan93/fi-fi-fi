# Iceland Map Workflow

This project has an interactive map of Iceland built with a build-time pipeline. D3 projects geographic data at build time — zero D3 ships to the browser. The browser gets static images + CSS.

## How it works

```
data/locations.json          ← Single source of truth for locations
data/iceland.geojson         ← Coastline (GeoJSON)
data/routes/*.geojson        ← One file per hiking route
        │
        ▼
scripts/generate-map.ts      ← Bun script using D3 (devDependency)
scripts/process-terrain.py   ← Python/Pillow terrain processing
        │
        ├──▶ src/map/locations.json    (computed x/y/tx/ty positions)
        ├──▶ src/map/locations.css     (generated :has() CSS rules)
        ├──▶ public/assets/*.webp      (terrain + route images)
        └──▶ src/map/iceland.svg       (dev preview only)
        │
        ▼
index.html                   ← Markers as HTML divs, nav as radio buttons
src/map/map.css              ← Base styles (layout, layers, transitions)
```

## Key principle: markers are HTML divs, not SVG

Markers are `<div>` elements with `position: absolute; left: X%; top: Y%` inside a 16:9 aspect-ratio container. They use `<label for="map-{id}">` to trigger radio buttons — pure CSS zoom via `:has()` + `@property`. No JavaScript for map interactions.

The marker `left`/`top` positions come from `locations.json` (computed by D3 projection). Apply `transform: translate(-5px, -5px)` to center the dot on the geographic point (not its top-left corner).

## Adding a new location

1. Edit `data/locations.json`:
```json
{
  "id": "new",
  "name": "Location Name",
  "coords": [-18.5, 65.0],
  "label": "Region Label",
  "info": "Description in Icelandic.",
  "routes": []
}
```

2. Run `bun run generate-map` — outputs computed positions and CSS values.

3. In `index.html`, add three things:
   - Marker in `.map__markers`: `<div class="marker" style="left: X%; top: Y%"><label for="map-{id}">...</label></div>`
   - Detail panel in `.map__details`: `<div class="map__detail" data-location="{id}">...</div>`
   - Radio + label in `.map__nav`: `<input type="radio" name="map-loc" id="map-{id}" class="sr-only" /><label for="map-{id}" class="map__nav-btn">Name</label>`

4. The CSS rules (`:has()` for transforms, details, active buttons) are in `src/map/locations.css` — generated by the build script. No manual CSS needed.

## Adding a new route

1. Get GeoJSON — from OpenStreetMap via `scripts/convert-trail.ts`, GPX conversion, or manual coordinates.
2. Save to `data/routes/{id}.geojson` — must be a GeoJSON Feature with LineString geometry.
3. Link in `data/locations.json` on relevant locations: `"routes": ["route-id"]`
4. Run `bun run generate-map` — renders route as transparent WebP at `public/assets/route-{id}.webp`
5. In `index.html`, add the route image in `.map__image`: `<img src="/assets/route-{id}.webp" class="route-overlay" />`

## Getting route data from OpenStreetMap

```bash
# 1. Query Overpass API for a hiking trail relation
curl -s "https://overpass-api.de/api/interpreter" \
  --data-urlencode 'data=[out:json];relation["name"="Trail Name"]["route"="hiking"];(._;>;);out body;' \
  -o /tmp/trail-raw.json

# 2. Convert to clean GeoJSON (handles parallel routes, stitching, simplification)
bun scripts/convert-trail.ts
```

The convert script uses Dijkstra to find the shortest path through OSM's messy relation data (which often has parallel alternatives). It simplifies with Douglas-Peucker. Adjust `TOLERANCE` in the script for smoothness.

## Terrain processing

The terrain image is ESRI hillshade, processed by Python:

```bash
# 1. generate-map.ts fetches raw ESRI terrain and saves to public/assets/raw-*.png
bun run generate-map

# 2. Python processes: invert, S-curve contrast, clarity, save as WebP
uv run scripts/process-terrain.py
```

Key settings in `process-terrain.py`:
- `max_dark = 0.50` — terrain intensity (0.3 = subtle, 0.7 = strong)
- `s_curve strength = 0.7` — midtone separation
- White background — critical for `mix-blend-mode: multiply` on warm paper (#c5bdb9)

## CSS zoom mechanics

The map uses `@property` registered custom properties for smooth transitions:

```css
.map__image {
  transform:
    translate(calc(var(--map-tx) * 1%), calc(var(--map-ty) * 1%))
    scale(var(--map-scale));
}

/* Generated per-location rule */
.map:has(#map-rvk:checked) .map__image {
  --map-scale: 2.8;
  --map-tx: 35.9;
  --map-ty: -44.7;
}
```

Transform formula: `tx = -(x - 50) * (scale - 1)`, `ty = -(y - 50) * (scale - 1)`. This centers the target point in the viewport when scaled.

## 16:9 alignment contract

Everything aligns because of a locked aspect ratio:

- `.map__inner` has `aspect-ratio: 1920/1080` (16:9)
- Terrain image fills it at `width: 100%; height: 100%` — no `object-fit: cover`
- Route overlay images are the same dimensions, positioned `absolute; inset: 0`
- Marker `left`/`top` percentages reference the same 16:9 box

Breaking this contract (adding `object-fit: cover`, changing the aspect ratio, or positioning markers relative to a different container) will cause alignment drift.
