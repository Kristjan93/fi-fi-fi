# Phase 1: Responsive Map Layout — Design

> Validated design for Phase 1 of `docs/iceland-map-implementation-spec.md`.
> Decisions made during brainstorming session 2026-03-26.

---

## Context

The Iceland interactive map is locked to 16:9 (1920×1080). On iPad (4:3), it renders as a horizontal strip with dead space. On phones, it's nearly unusable. Phase 1 changes the coordinate space to 4:3 and makes the map fit every screen.

## Decisions

| Question | Decision |
|---|---|
| Golden viewport | iPad Landscape (4:3) — 1440×1080 |
| Detail panel placement | Inside the map container (current approach) |
| Phone experience | Just make it not break — polish in Phase 4 |
| `<picture>` fallback | Keep AVIF + WebP fallback (overrides spec task 1.3) |
| Implementation order | Pipeline-first — regenerate assets before CSS changes |

---

## 1. Data extraction — `data/locations.json`

**Problem:** Location source data (coords, name, label, info) is hardcoded in `generate-map.ts`. Adding a location means editing three files.

**Change:**
- Create `data/locations.json` as the single source of truth — geographic coords + metadata only
- `generate-map.ts` reads from this file, deletes its hardcoded MARKERS array
- Build output `src/map/locations.json` gets computed `x, y, tx, ty` values appended
- Routes stay in `generate-map.ts` (only one route, tightly coupled to pipeline)

**Source format:**
```json
[
  { "id": "rvk", "name": "Reykjavík", "label": "Höfuðborg",
    "info": "Norðurljós borgarinnar...", "coords": [-21.9426, 64.1466] }
]
```

## 2. Build pipeline — `generate-map.ts`

**Constants change:**
- `W = 1440` (was 1920)
- `H = 1080` (unchanged)
- `PADDING = 25` (was 50)
- `MAP_SCALE = 2.8` (unchanged)
- `TERRAIN_SCALE = 3` (unchanged — terrain fetched at 4320×3240)

**New output — `src/map/locations.css`:**

Generated CSS with per-location `:has()` rules for transform values and detail panel visibility:
```css
/* Auto-generated by generate-map.ts — do not edit */
.map:has(#map-rvk:checked) .map__image {
  --map-scale: 2.8; --map-tx: 35.9; --map-ty: -44.7;
}
.map:has(#map-rvk:checked) .map__detail[data-location="rvk"] {
  display: block; opacity: 1; /* ... */
}
```

**What stays in hand-written `map.css`:**
- Generic rules (hide markers when any location checked, highlight active nav button)
- All layout, sizing, transitions, responsive breakpoints

**Connection:** `map.css` imports via `@import './locations.css';`

**Net effect:** Adding a location = edit `data/locations.json` + run pipeline. No manual CSS.

## 3. CSS container — responsive layout

**Change `.map__inner` from 16:9 to 4:3:**
```css
.map__inner {
  width: 100%;
  aspect-ratio: 4 / 3;
  max-height: 100%;
  position: relative;
}
```

**Behavior per device:**

| Device | Aspect | Result |
|---|---|---|
| iPad landscape | 4:3 | Fills viewport exactly |
| Desktop 16:9 | wider | Fills height, warm paper on sides |
| iPad portrait | 3:4 | Fills width, warm paper above/below |
| Phone portrait | ~9:19 | Fills width, warm paper above/below — functional |

No new breakpoints. Existing 480px mobile breakpoint stays. Container math handles the rest via `aspect-ratio` + `max-height: 100%`.

## 4. Touch targets — marker labels

**Problem:** Marker dots are 10px. Apple HIG minimum is 44px.

**Fix:** Expand the existing `<label>` wrapper with padding + negative margin:
```css
.marker label {
  padding: 17px;     /* (44 - 10) / 2 */
  margin: -17px;     /* no layout shift */
  cursor: pointer;
}
```

Visible dot stays 10px. Tappable area becomes 44px. Dot stays centered on geographic point. No alignment drift.

## 5. Spec + doc updates

- **`docs/iceland-map-implementation-spec.md` task 1.3:** Rewrite from "Drop `<picture>`" to "Keep `<picture>` with AVIF source + WebP fallback"
- **`docs/iceland-map-implementation-spec.md`:** Update dimension references (1920→1440, 50px→25px padding)
- **`CLAUDE.md`:** No change needed — the "AVIF only" note refers to `process-terrain.py` output format, not HTML markup

## Execution order

1. Extract source data → `data/locations.json`
2. Update `generate-map.ts` — new dimensions, read from data file, generate `locations.css`
3. Run pipeline (`bun run generate-map`) + terrain processing (`uv run scripts/process-terrain.py`)
4. Update `map.css` — aspect-ratio 4/3, `@import './locations.css'`, remove hand-written per-location rules
5. Update `index.html` — marker positions from new computed data
6. Touch targets — 44px hit areas via padding/margin on marker labels
7. Update spec task 1.3 — keep `<picture>` fallback
8. Cross-device verification (iPad landscape, desktop 16:9, iPad portrait, phone)
