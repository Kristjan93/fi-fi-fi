# Phase 1: Responsive Map Layout + Hut Data — Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Change the Iceland map from 16:9 (1920×1080) to 4:3 (1440×1080), replace 7 placeholder landmarks with 16 FÍ mountain huts from SQLite, remove nav sidebar (markers ARE the navigation), add dots-only overview with labels on zoom, and make it fit every screen.

**Architecture:** Pipeline-first. Update `generate-map.ts` to read huts from SQLite via `map-data.ts`, project at 1440×1080, generate per-hut CSS. Rebuild HTML with 16 hut markers and richer detail panels. Remove nav sidebar, add back-to-overview button.

**Tech Stack:** D3 (projection), Sharp (image processing), Pillow/NumPy (terrain), SQLite (via bun:sqlite), vanilla CSS, Bun runtime.

**Design spec:** `docs/superpowers/specs/2026-03-26-phase1-responsive-map-layout-design.md`

**Key decisions:**
- Golden viewport: iPad Landscape 4:3
- Data source: SQLite (`data/map.db`) via `scripts/map-data.ts`
- Navigation: No button sidebar — click markers directly, "back to overview" button
- Markers: Dots only at overview, labels appear on hover (desktop) or when zoomed
- Detail panel: Compact — name, stats (elevation · beds · season), info, trail/attraction list
- Touch targets: 44px minimum
- `<picture>` fallback: Keep AVIF + WebP

```typescript
import { openMapDb, getHuts, getTrailsForHut, getAttractionsForHut } from "./map-data";

const db = openMapDb();
const huts = getHuts(db);

// Map huts to the format the pipeline expects
const MARKERS = huts.map((h) => ({
  id: h.id,
  name: h.name,
  coords: [h.lon, h.lat] as [number, number],
  label: h.label,
  info: h.info,
  beds: h.beds,
  elevation: h.elevation,
  open: h.open,
  source: h.source,
  trails: getTrailsForHut(db, h.id),

}));

db.close();
```

```typescript
await Bun.write("src/map/locations.css", locationsCss);
```
